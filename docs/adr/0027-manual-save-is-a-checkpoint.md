# 수동 저장은 되돌아올 지점을 선언한다 — 자동저장은 유실만 막고, Ctrl+S가 `checkpoint`를 남긴다

> **Status**: Proposed · **Tags**: `collaboration` · **Date**: 2026-07-31 · **Supersedes**: — · **Related**: ADR-0014, ADR-0023, ADR-0024, ADR-0025

프로젝트 콘텐츠는 600ms 디바운스 자동저장으로만 서버에 반영된다. 여기에 **명시적 저장(Ctrl+S)** 을 얹되, 자동저장과 기능이 겹치지 않도록 역할을 나눈다.

- **자동저장은 유실 방지만 한다.** 지금처럼 조용히 PATCH하고 아무 기록도 남기지 않는다.
- **수동 저장은 복구 지점의 선언이다.** 대기 중인 저장을 즉시 밀어넣고, 그 시점을 **`checkpoint`라는 새 스냅샷 종류**로 버전 기록에 남긴다.
- **편집 모드를 나갈 때는 무조건 한 번 저장한다** — 단 기록은 남기지 않는다. 이것은 안전망이지 선언이 아니다.

## 문제

### 1. 편집 모드를 나가는 순간 마지막 편집이 사라진다

`readOnly`는 `!canEdit || !editMode || bumped || lockedByOther`이고(ADR-0025), 페이지는 `suspended: previewing || readOnly`로 자동저장을 멈춘다. `suspended`가 켜지면 자동저장은 **대기 중인 디바운스를 `cancel()`** 한다.

따라서 마지막 타이핑이나 노드 드래그 후 600ms 안에 "편집 종료"를 누르면, 그 편집은 서버에 도달하지 못한 채 취소된다. 사용자에게는 아무 신호도 없다. 편집 모드를 자주 드나들도록 만든 ADR-0025가 이 창을 자주 열리게 했다.

### 2. 자동저장에는 "여기가 중요하다"를 말할 방법이 없다

버전 기록의 시간 해상도는 30분(`auto_fine`)이다. 방금 끝낸 작업 단위를 기록에 남기려면 30분을 기다리거나, 이름을 붙인 수동 스냅샷(ADR-0023)을 만들어야 한다. 후자는 영구 보관·프로젝트당 50개 상한이라 "일단 여기까지 해뒀다" 용도로 쓰기엔 무겁다.

## Considered Options

### 자동저장과 수동 저장의 역할 분담

- **자동저장 유지 + Ctrl+S는 체크포인트 (채택)**: 자동저장이 유실을 막고, Ctrl+S는 자동저장이 할 수 없는 일(되돌아올 지점 선언)만 한다. 두 기능이 겹치지 않으므로 "굳이 Ctrl+S를 누를 이유"가 분명하다. 협업 도구라 리스 만료·강제 회수·탭 종료가 실제로 일어나는데, 그때 미저장분을 만들지 않는다.
- **자동저장 제거, 수동 저장만 (기각)**: "저장했다"가 명확해지지만, 리스 만료·강제 회수·크래시에서 미저장분이 통째로 날아간다. 그것을 막으려면 "닫을 때 저장할까?" 확인 다이얼로그와 `beforeunload` 경고를 새로 만들어야 하는데, 그건 ADR-0024가 없애려던 "나중에 알게 되는 실패"를 되살린다.
- **Ctrl+S는 즉시 저장만 (기각)**: 구현이 가장 작지만 자동저장과 결과가 같아 사용자가 누를 이유가 없다. 문제 2를 그대로 남긴다.

### 수동 저장이 남기는 스냅샷의 종류

- **새 kind `checkpoint` (채택)**: 라벨 없음, 직전 `checkpoint`와 `content_hash`가 같으면 새 행을 만들지 않음, `auto_fine`과 같은 90일 보관 후 자동 prune, 개수 상한 없음. 버전 기록 패널에서 "저장" 배지로 식별된다. `kind`는 평문 `String(16)`이고 DB enum도 CHECK 제약도 없으므로 **Alembic 마이그레이션이 필요 없다**.
- **기존 `manual` 무제로 기록 (기각)**: 백엔드 변경이 없지만, 프로젝트당 50개 상한을 며칠 만에 소진해 어느 순간 저장이 에러로 실패한다. 영구 보관이라 수동 탭이 무제 행으로 덮이고, "라벨=식별자"라는 ADR-0023의 모델이 깨진다.
- **기존 `auto_fine`으로 기록 (기각)**: 보관·prune·dedup이 공짜로 붙지만 패널 배지가 "30분"으로 찍혀 **사용자가 직접 찍은 지점을 자동 스냅샷과 구분할 수 없다** — 수동 저장을 의미 있게 만들자는 목적 자체가 무너진다. `auto_fine`은 이미 두 의미(30분 주기 + 원복 안전망)로 과적재되어 있어 세 번째를 얹으면 "이 행은 왜 생겼나"를 설명할 수 없게 된다.

### 편집 모드 종료 시의 강제 저장도 기록을 남기는가

- **저장만, 기록 없음 (채택)**: 종료 flush는 유실 방지이지 지점 선언이 아니다. 편집 모드는 드나들기 쉬우므로(ADR-0025) 매번 기록을 찍으면 `checkpoint`가 사실상 두 번째 자동 스냅샷이 되고 "내가 직접 찍은 지점"이라는 의미가 희석된다. 내용은 어차피 다음 30분 스냅샷이 집는다.
- **종료 시에도 checkpoint (기각)**: 세션 경계가 기록에 남지만 위의 희석 비용이 이득보다 크다.

### 종료 flush와 리스 반납의 순서

- **flush를 await한 뒤 반납 (채택)**: 백엔드 `take_or_conflict`는 리스가 free면 **획득**한다. 반납 후에 PATCH를 보내면 방금 놓은 락을 그 PATCH가 되살려, 편집을 끝낸 사람이 계속 락을 쥔 것처럼 보인다. 순서를 호출부가 정하게 두면 언젠가 틀리므로, `onEntered`와 대칭인 `onExiting` 훅으로 `useEditLease` 안에 넣어 `setEditMode(false)` 이전에 await한다.
- **반납 후 flush (기각)**: 위의 락 되살아남이 발생한다.
- **페이지가 순서를 조립 (기각)**: 지금은 맞게 쓸 수 있으나 순서 규칙이 코드 어디에도 강제되지 않는다.

### flush가 실패하면

- **편집 모드를 유지하고 알린다 (채택)**: 저장하지 못한 채 읽기 모드로 내려보내면 유실이 확정되고, 읽기 모드에서는 되살릴 방법도 없다. 실패를 토스트로 알리고 사용자가 다시 시도하게 둔다. 단 409(뺏김·stale)는 이미 리스가 없는 것이므로 기존 `reportConflict` → 충돌 다이얼로그 경로를 탄다(ADR-0024).
- **실패해도 나간다 (기각)**: 조용한 유실. 고치려던 문제 그 자체.

### 탭 종료·새로고침 순간의 미저장분

- **다루지 않는다 (채택, 이번 범위 밖)**: `pagehide`에서 keepalive PATCH를 추가하면 같은 keepalive인 `releaseLock`과 도착 순서가 보장되지 않아 위의 "락 되살아남"이 확률적으로 발생한다. 회피하려면 미저장분이 있을 때 반납을 생략해야 하는데, 그것은 "닫으면 즉시 반납"(ADR-0024)의 예외를 만드는 별도 결정이다. 노출 창이 600ms이고 Ctrl+S와 종료 flush가 주요 경로를 덮으므로 지금 감수한다.

## Consequences

- 스냅샷 종류가 넷이 된다: `auto_fine` · `auto_coarse` · `manual` · **`checkpoint`**. 마이그레이션은 없다(모델 docstring만 갱신). prune 대상에 `checkpoint`가 `auto_fine`과 같은 보관 기간으로 추가된다.
- `POST /api/projects/:id/snapshots`가 `kind: 'manual' | 'checkpoint'`를 받는다(기본 `manual`, 기존 호출부 무영향). `checkpoint`는 label·overwrite·50개 상한을 모두 무시한다.
- 버전 기록 패널의 시간순 탭에 `checkpoint`가 함께 나오고 "저장" 배지로 구분된다. 그 탭은 더 이상 자동 스냅샷만 담지 않으므로 라벨을 그에 맞게 고친다.
- `useProjectAutosave`가 `flush()`를 노출하고, 내부 mutation이 `mutateAsync`가 된다. `useEditLease`에 `onExiting`이 생긴다.
- **30분 job은 최신 `auto_fine`하고만 dedup을 비교한다** — 체크포인트 직후 변경이 없어도 `auto_fine`이 하나 더 생긴다. 30분에 최대 1행이라 기존 중복 수준이고, 비교 대상을 넓히는 복잡도를 지금 지불하지 않는다.
- 토스트가 앱 전역 알림 수단으로 도입된다(`shared/ui/toast.tsx`, radix Toast 프리미티브 — 새 의존성 없음). 기존 인라인 에러 표시는 이번에 옮기지 않는다.
